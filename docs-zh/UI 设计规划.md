# RarZap UI 设计规划文档

**版本**：1.0  
**日期**：2026-10-11  
**目标平台**：Windows 11、macOS 14+、Ubuntu 24.04 / Debian 12+  
**技术栈**：GPUI 0.2.x + gpui-component 0.5.x


## 一、设计原则

2026 年的 UI 设计正在从“视觉表演”转向“认知清晰”。Envato 的趋势报告指出，今年的核心变化是“用认知清晰换掉视觉奇观”，设计奖励判断力和克制，而非新奇感。Liquid UI 则强调界面不应展示软件能做什么，而应展示用户当前需要做什么。

RarZap 作为一款压缩文件转换工具，设计应遵循三个原则：

**安静（Calm）** 。工具类软件的核心价值是“用完即走”，界面不应抢夺注意力。除进度条和状态徽标外，大量区域保持低对比度、低饱和度的中性色调。动画只用于解释状态变化，不用于装饰。

**流动（Liquid）** 。界面根据用户当前所处的任务阶段自动调整信息密度。空状态时展示简洁的拖放区域和引导文案；文件加载后切换为高信息密度的列表视图；转换完成后突出摘要信息和后续操作。用户不需要在多个“页面”之间跳转，信息在同一窗口内平滑过渡。

**精准（Precise）** 。每个视觉元素都有明确的功能目的。间距、圆角、颜色、字重全部来自设计系统的 token，应用代码中不出现硬编码的样式值。这也符合 GPUI 社区的最佳实践：所有颜色从 `cx.theme()` 获取，所有间距从 `cx.design()` 获取，应用代码中不得出现 `rgb()`、`rgba()` 或任何颜色字面量。


## 二、视觉方向：从 2026 趋势到 GPUI 可落地的选择

2026 年主流趋势中，Bento Grid（便当网格）和 Glassmorphism 2.0（精细玻璃拟态）是最具代表性的两种方向。但需要区分哪些能在 GPUI 中完整实现，哪些需要降级。

### 2.1 采纳：Bento Grid 的信息组织逻辑

Bento Grid 通过圆角矩形卡片组合内容，适合 RarZap 的批量任务概览场景。不直接照搬 Apple 风格的等宽网格，而是将其转化为 **“任务阶段驱动的布局变体”**：

- **空状态**：中央大卡片，占窗口主要面积，内含拖放区域和简短引导
- **加载中**：左侧文件列表占 70% 宽度，右侧摘要面板占 30%
- **完成**：全宽摘要卡片，下方可展开失败详情列表

布局切换通过 GPUI 的条件渲染实现——在 `render()` 中根据 `self.stage` 返回不同的元素树。GPUI 的布局阈值是显式的 Rust 条件，而非 CSS 媒体查询，这恰好适合阶段驱动的布局切换。

### 2.2 降级：玻璃拟态的实现方式

Glassmorphism 2.0 依赖 `backdrop-filter: blur(24px) saturate(180%)` 实现多层半透明模糊效果。GPUI 的模糊支持受限于平台：根据 gpui-component 的源码，`paint_backdrop_blur` 仅在 macOS 的 Metal 后端可用，Windows 和 Linux 上不可用。

**降级策略**：采用“半透明表面 + 1px 细边框”替代真正的背景模糊。使用 `theme.surface` 的 92% 不透明度作为面板背景色，配合 `theme.border` 的 1px 边框，在视觉上接近毛玻璃的“轻盈感”，但不依赖平台模糊支持。这样三平台表现一致，不会出现 macOS 有模糊、Windows 没有的割裂感。

### 2.3 避免：野蛮主义与高饱和霓虹

2026 年趋势中出现了“野蛮主义回归”和“赛博朋克配色”的声音。这两种风格与 RarZap 的“安静”定位直接冲突，明确排除。深色模式使用深灰蓝而非纯黑（`#0F1117` 类似色域），避免霓虹点缀。


## 三、设计系统 Token

### 3.1 色彩

遵循 GPUI 社区的 token 规范，所有颜色定义在 Theme 中，应用代码只引用语义化的 token 名称。gpui-component 内置 `Theme` 和 `ThemeColor`，支持通过变量配置多主题。

**浅色模式：**

| Token | 值 | 用途 |
|---|---|---|
| `background` | `#F7F8FA` | 窗口根背景 |
| `surface` | `#FFFFFF` | 卡片、面板背景 |
| `surface_hover` | `#F0F1F3` | 悬停态背景 |
| `muted` | `#E8EAED` | 分隔线、禁用态背景 |
| `border` | `#E2E4E8` | 边框、分割线 |
| `text_primary` | `#1A1D23` | 主标题、正文 |
| `text_secondary` | `#5F6572` | 辅助说明文字 |
| `text_muted` | `#9CA3AF` | 时间戳、次要元信息 |
| `accent` | `#3B82F6` | 主按钮、进度条、选中态 |
| `accent_hover` | `#2563EB` | 主按钮悬停 |
| `error` | `#EF4444` | 错误状态 |
| `success` | `#10B981` | 完成状态 |
| `warning` | `#F59E0B` | 警告状态 |

**深色模式：**

| Token | 值 | 用途 |
|---|---|---|
| `background` | `#0F1117` | 窗口根背景 |
| `surface` | `#1A1D23` | 卡片、面板背景 |
| `surface_hover` | `#252830` | 悬停态背景 |
| `muted` | `#2A2D35` | 分隔线、禁用态背景 |
| `border` | `#2E3138` | 边框、分割线 |
| `text_primary` | `#E8EAED` | 主标题、正文 |
| `text_secondary` | `#9CA3AF` | 辅助说明文字 |
| `text_muted` | `#5F6572` | 时间戳、次要元信息 |
| `accent` | `#60A5FA` | 主按钮、进度条（深色模式提亮） |
| `accent_hover` | `#3B82F6` | 主按钮悬停 |

深色模式的强调色比浅色模式提亮约 20%，原因是在深色背景上，`#3B82F6` 的对比度不足 WCAG AA 标准。2026 年的桌面应用设计趋势中，深色模式已从“可选功能”变为“生产级应用的标配信号”，专门调整暗色下的对比度和舒适度是必要投入。

### 3.2 字体

**字体族**：跨平台统一使用 **Inter** 作为 UI 字体，**JetBrains Mono** 作为文件大小、路径等需要等宽显示的场景。GPUI 通过 `font-kit` 特性支持系统字体加载，也可以将字体文件打包进二进制。

**排版层级：**

| 层级 | 字号 | 字重 | 行高 | 字间距 | 用途 |
|---|---|---|---|---|---|
| `display` | 24px | 600 | 1.3 | -0.02em | 空状态标题 |
| `heading` | 18px | 600 | 1.4 | -0.01em | 面板标题 |
| `body` | 14px | 400 | 1.5 | 0 | 正文、文件名 |
| `body-strong` | 14px | 500 | 1.5 | 0 | 按钮文字、强调 |
| `caption` | 12px | 400 | 1.4 | 0.01em | 辅助信息、文件大小 |
| `mono` | 13px | 400 | 1.5 | 0 | 文件路径、技术信息 |

2026 年的排版趋势中，大尺寸文本使用负字间距（-0.02em 在 30px+ 场景），小尺寸文本趋向正常间距，这与 Inter 字体本身的优化方向一致。

### 3.3 间距与圆角

**间距系统**：基于 **4px 基准单位**，所有间距为 4 的整数倍。

| Token | 值 | 用途 |
|---|---|---|
| `space-1` | 4px | 图标与文字间距 |
| `space-2` | 8px | 紧密元素间距 |
| `space-3` | 12px | 列表项内间距 |
| `space-4` | 16px | 卡片内边距 |
| `space-5` | 20px | 面板内边距 |
| `space-6` | 24px | 面板间间距 |
| `space-8` | 32px | 大区块间距 |
| `space-12` | 48px | 空状态垂直间距 |

**圆角系统：**

| Token | 值 | 用途 |
|---|---|---|
| `radius-sm` | 6px | 按钮、输入框、小徽标 |
| `radius-md` | 10px | 卡片、面板 |
| `radius-lg` | 14px | 大卡片、拖放区域 |
| `radius-full` | 9999px | 圆形状态指示器 |

GPUI 的 `.rounded(px(8.))` 链式调用直接支持这些值。Bento Grid 趋势中推荐的 16–24px 圆角主要面向大尺寸卡片，RarZap 的卡片尺寸偏小，14px 是视觉上更协调的上限。


## 四、布局架构

### 4.1 窗口规格

| 属性 | 值 |
|---|---|
| 默认尺寸 | 720 × 520 px |
| 最小尺寸 | 560 × 420 px |
| 最大尺寸 | 无限制 |
| 标题栏 | 自定义标题栏（`gpui-component` 的 `TitleBar`），三平台一致 |

GPUI 支持客户端装饰窗口，`WindowChrome` 提供 resize-edge hitboxes。在 Linux 上，GPUI 默认渲染自定义窗口边框和阴影，因为 GNOME/KDE 的客户端装饰行为不一致。

中央拖放区域使用 `radius-lg`（14px）圆角，背景为 `surface`，边框为 1px `border`。拖拽悬停时边框变为 `accent` 色，背景轻微提亮。文件对话框通过 GPUI 内置的 `prompt_for_paths()` 调用系统原生选择器。

## 五、组件规格

### 5.1 组件总览与 GPUI 能力对照

| 界面区域 | 推荐组件 | GPUI / gpui-component 能力 | 可用性 |
|---|---|---|---|
| 窗口标题栏 | `TitleBar` | gpui-component 内置，三平台一致 | ✅ 直接可用 |
| 主操作按钮 | `Button` | 支持 `primary` / `secondary` / `danger` 变体，`xs`–`lg` 尺寸 | ✅ 直接可用 |
| 文件列表 | `Table` / `List` | 虚拟化渲染，支持大数据集流畅滚动 | ✅ 直接可用 |
| 进度条（整体） | `Progress` | 线性进度条，值变化时平滑过渡动画 | ✅ 直接可用 |
| 进度条（行内） | `Progress` | 同上，嵌入 Table 行内使用 | ✅ 直接可用 |
| 状态徽标 | `Badge` | 支持多种颜色变体 | ✅ 直接可用 |
| 错误弹窗 | `Dialog` | 模态对话框，支持 backdrop 和自定义尺寸 | ✅ 直接可用 |
| 通知提示 | `Notification` / `Toast` | gpui-component 内置通知系统 | ✅ 直接可用 |
| 文件路径输入 | `Input` | 单行文本输入，支持前缀/后缀元素 | ✅ 直接可用 |
| 输出目录选择 | 原生对话框 | `prompt_for_paths()` / `prompt_for_new_path()` | ✅ 直接可用 |
| 空状态拖放区 | 自定义 `div()` | Flexbox 布局 + 边框/圆角/悬停态 | ✅ 需自行组合 |
| 摘要卡片 | 自定义 `div()` | 同上 | ✅ 需自行组合 |

### 5.2 按钮规格

| 变体 | 背景 | 文字 | 用途 |
|---|---|---|---|
| Primary | `accent` | `text_on_accent` | “选择文件”“开始转换” |
| Secondary | `surface` + `border` | `text_primary` | “选择文件夹”“更改” |
| Ghost | 透明 | `text_secondary` | “取消全部”“重试” |
| Danger | `error` | `text_on_accent` | “删除”“清空列表” |

按钮尺寸：默认 `md`（高度 32px），紧凑场景用 `sm`（高度 28px）。圆角 `radius-sm`（6px）。GPUI 的 `.shadow_md()` 仅用于 Primary 按钮，且阴影透明度控制在 0.15 以内，保持克制。

### 5.3 进度条规格

**整体进度条**：固定在窗口底部，高度 3px，无圆角（贴边）。颜色为 `accent`，背景为 `muted`。右侧显示“整体进度 33%”文字，用 `caption` 层级。

**行内进度条**：嵌入文件列表的每一行，高度 2px，位于文件名下方。转换中的行显示实际进度，等待中的行显示空槽，已完成的行显示满槽。

`gpui-component` 的 `Progress` 组件使用 `window.use_keyed_state` 跟踪前值，在值变化时产生平滑插值动画。这个动画长度应控制在 200ms 以内，确保进度更新感觉是“响应式”的而非“滞后”的。

### 5.4 空状态拖放区

使用 GPUI 的 Flexbox 布局构建：

```rust
div()
    .flex()
    .flex_col()
    .items_center()
    .justify_center()
    .gap(px(design.spacing.section_gap))
    .p(px(design.spacing.card_padding))
    .bg(cx.theme().surface)
    .border(px(1.))
    .border_color(if is_dragging {
        cx.theme().accent
    } else {
        cx.theme().border
    })
    .rounded(px(design.radius.lg))
```

拖拽进入时，边框变为 `accent` 色（而非改变背景色），避免视觉跳跃过大。拖拽离开时恢复。过渡动画通过 GPUI 的 `Transition` 实现，时长 150ms，曲线使用 `ease-out`。


## 六、动效规范

2026 年的设计趋势强调“动效解释状态变化，而非表演”。GPUI Kit 提供三层动效能力：`transition`（已知时长的目标值过渡）、`spring`（弹性动画）和 `with_animation`（已知起止的序列动画），所有动效都尊重系统的 reduced-motion 偏好设置。

| 场景 | 动效类型 | 时长 | 说明 |
|---|---|---|---|
| 面板展开/收起 | `transition` | 200ms | 高度 + 透明度同步变化 |
| 按钮悬停 | `transition` | 150ms | 背景色过渡 |
| 进度条更新 | 内部插值 | 200ms | Progress 组件自动处理 |
| 列表项状态变更 | 颜色过渡 | 200ms | 状态文字和颜色渐变 |
| 空状态 → 加载状态 | `Presence` | 300ms | 旧内容淡出，新内容淡入 |
| Toast 通知 | `spring` | 400ms | 从底部滑入，轻微回弹 |

**明确排除的动效**：页面级滑动转场、视差效果、装饰性粒子效果、自动播放的图标动画。Liquid UI 的核心理念是“界面在用户意图下流动”，而非“界面持续运动”。RarZap 的界面在空闲状态下应完全静止。


## 七、平台适配

### 7.1 窗口装饰

GPUI 在 Linux 上默认使用客户端装饰，需要自行处理窗口边框和阴影。在 Windows 和 macOS 上，`gpui-component` 的 `TitleBar` 组件统一三平台的标题栏外观。

| 平台 | 窗口装饰策略 |
|---|---|
| macOS | 客户端装饰，红绿灯按钮保留系统样式 |
| Windows | 客户端装饰，窗口控制按钮样式与 Windows 11 一致（矩形悬停区域） |
| Linux | 客户端装饰，窗口边框使用 1px `border` 色，阴影由 GPUI 渲染 |

### 7.2 文件对话框

三平台统一通过 GPUI 的 `prompt_for_paths()` 调用系统原生文件选择器。在 Linux 上，GPUI 通过 XDG Desktop Portal 与 GNOME/KDE 的文件对话框对接，行为与系统一致。

### 7.3 高 DPI 适配

GPUI 的 `px()` 单位是逻辑像素，会自动根据窗口的 `scale_factor` 缩放。所有设计 token 中的像素值均按逻辑像素定义，不进行手动 DPI 计算。在 200% 缩放的 Windows 机器上，界面元素自动放大一倍。


## 八、无障碍

### 8.1 色彩对比度

所有文字/背景组合满足 WCAG AA 标准（对比度 ≥ 4.5:1）：

| 组合 | 对比度 | 结果 |
|---|---|---|
| `text_primary` / `background`（浅色） | 15.2:1 | ✅ |
| `text_secondary` / `background`（浅色） | 6.8:1 | ✅ |
| `text_primary` / `surface`（深色） | 13.1:1 | ✅ |
| `text_secondary` / `surface`（深色） | 5.4:1 | ✅ |
| `accent` / `background`（浅色，用于进度条） | 4.6:1 | ✅ |
| `error` / `surface`（浅色，用于错误文字） | 4.7:1 | ✅ |

### 8.2 状态双重编码

任务状态不仅通过颜色区分，同时使用文字标签和图标符号：

- 已完成：绿色 ✓ + “完成”文字
- 失败：红色 ✗ + “失败”文字
- 等待中：灰色 ○ + “等待中”文字

这确保色觉障碍用户也能准确识别状态。

### 8.3 键盘导航

| 快捷键 | 功能 |
|---|---|
| `Ctrl/Cmd + O` | 打开文件选择器 |
| `Ctrl/Cmd + Shift + O` | 打开文件夹选择器 |
| `Ctrl/Cmd + Enter` | 开始转换 |
| `Esc` | 取消当前操作 / 关闭对话框 |
| `Tab` / `Shift + Tab` | 在可交互元素间移动焦点 |

GPUI 的 `KeyBinding` 机制支持跨平台快捷键定义。`gpui-component` 的表单组件内置焦点管理，`Tab` 导航开箱即用。

### 8.4 Reduced Motion

通过 GPUI 的 reduced-motion 偏好检测，在用户开启“减少动画”时：

- 所有 `transition` 时长降为 0ms
- `spring` 动画替换为即时状态切换
- `Presence` 的淡入淡出保留但时长减半

GPUI Kit 的动效系统原生支持这一偏好，无需额外实现。


## 九、主题切换

### 9.1 跟随系统

默认行为：跟随操作系统的浅色/深色设置。GPUI 通过平台 API 检测系统主题，在主题变更时触发重新渲染。

### 9.2 手动覆盖

在标题栏右侧提供一个主题切换按钮，循环切换：**跟随系统 → 浅色 → 深色**。用户选择持久化到本地配置文件。

### 9.3 主题实现

基于 `gpui-component` 的 `Theme` 和 `ThemeColor` 实现。多主题支持不在 `gpui-component` 本身，但可以基于 `Theme` 特性轻松实现。

```rust
// 初始化主题
Theme::light().init(cx);  // 或 Theme::dark()

// 在组件中使用
let theme = cx.theme();
div()
    .bg(theme.background)
    .text_color(theme.text_primary)
```
